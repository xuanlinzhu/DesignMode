# 分层架构图与层级映射

> 这页不是说“某个模式只能放在某一层”，而是给出**嵌入式系统中最常见的落点**。  
> 这样你可以先按系统层级找模式，而不是先背 23 个名字。

---

## 一、分层架构图

```text
┌──────────────────────────────────────────────────────────┐
│ 业务 / 应用层                                            │
│                                                          │
│  关注点：业务策略、运行模式、状态响应、事件处理            │
│  常见模式：Strategy / State / Observer / Command         │
└───────────────▲──────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────┐
│ 服务 / 协调层                                            │
│                                                          │
│  关注点：子系统入口、模块间协作、流程编排、对象族装配      │
│  常见模式：Facade / Mediator / Chain / Abstract Factory  │
└───────────────▲──────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────┐
│ 中间件 / 协议 / 配置层                                    │
│                                                          │
│  关注点：协议解释、树形配置、遍历、快照、复杂构建          │
│  常见模式：Interpreter / Composite / Iterator / Visitor  │
│           Memento / Builder                              │
└───────────────▲──────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────┐
│ 驱动抽象 / 适配层                                         │
│                                                          │
│  关注点：接口兼容、抽象与实现解耦、访问代理、增强包装      │
│  常见模式：Adapter / Bridge / Proxy / Decorator          │
│           Factory Method                                 │
└───────────────▲──────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────┐
│ 共享资源 / 基础设施层                                     │
│                                                          │
│  关注点：唯一资源、共享状态、对象复用、按需创建            │
│  常见模式：Singleton / Flyweight / Prototype / Proxy     │
└──────────────────────────────────────────────────────────┘
```

## 三、层与层之间的常见配合

| 上层诉求 | 典型配合 |
|---|---|
| 业务层切换模式，但底层差异不暴露 | 策略 + 桥接 + 抽象工厂 |
| 服务层要统一入口，底层有旧模块 | 外观 + 适配器 + 代理 |
| 协议层有树形配置，又要做批量导出检查 | 组合 + 迭代器 + 访问者 |
| 驱动层对象很多，RAM 紧张 | 享元 + 原型 + 单例 |
