## 1. 任务目标（必须满足）

实现一个基于 C 语言的观察者模式示例，用于模拟：

> **ADC 采集模块作为唯一数据生产者，在采集到新值后，通知多个订阅模块分别执行显示、报警、日志、通信等处理。**

必须体现：

- 存在**一个 Subject（发布者）**
- 存在**多个 Observer（订阅者）**
- ADC 模块是唯一数据源
- 多个订阅者都从同一个 ADC 数据源接收更新
- Subject 只负责发布通知，不负责决定各订阅者如何处理数据
- 订阅者之间互不调用
- 订阅者可以独立注册和移除

------

## 2. 核心场景（必须按此实现）

系统包含一个 ADC 数据源和多个数据消费者：

### 2.1 ADC 数据源（单生产者）

ADC 模块周期性获得一个新的采集值，例如：

```text
120
350
820
1023
```

每当采集值更新时：

- Subject 保存当前值
- Subject 遍历观察者列表
- Subject 调用每个观察者的更新接口
- 所有订阅者收到同一份最新值

------

### 2.2 多个订阅者（多消费者）

至少实现以下四类观察者：

- **显示观察者**：显示当前 ADC 值
- **报警观察者**：当 ADC 值超过阈值时报警
- **日志观察者**：记录 ADC 更新日志
- **通信观察者**：模拟上传当前 ADC 值

说明：

- 它们都订阅同一个 ADC 数据源
- 它们收到相同的 ADC 值
- 但响应逻辑互相独立

------

## 3. 模式要求（必须满足）

本示例必须明确体现观察者模式，而不是普通函数顺序调用。

必须体现：

- Subject 内部维护观察者列表
- Observer 通过统一接口接收更新
- Subject 数据变化时统一通知所有 Observer
- Observer 只依赖 Subject 推送的数据
- Subject 不依赖具体观察者业务逻辑

------

## 4. Subject（发布者）要求（必须存在）

必须定义 ADC Subject，例如：

```c
typedef struct adc_subject adc_subject_t;
```

Subject 必须承担两个职责：

### 4.1 保存当前 ADC 值

至少包含：

```c
int adc_value;
```

### 4.2 管理观察者列表

必须维护一个观察者数组或列表，用于保存已注册的观察者。

推荐使用固定容量数组，例如：

```c
#define MAX_OBSERVERS 8
```

------

## 5. Observer接口（必须存在）

必须定义抽象观察者接口，例如：

```c
typedef struct observer
{
    void (*update)(struct observer *self, int value);
} observer_t;
```

说明：

- `update` 是统一通知入口
- Subject 通知时只调用这个接口
- 不允许 Subject 直接调用具体观察者的专用函数

------

## 6. Subject接口（必须提供）

必须提供以下接口：

```c
void adc_subject_init(adc_subject_t *self);
int adc_subject_attach(adc_subject_t *self, observer_t *observer);
int adc_subject_detach(adc_subject_t *self, observer_t *observer);
void adc_subject_set_value(adc_subject_t *self, int value);
void adc_subject_notify(adc_subject_t *self);
```

语义要求：

### 6.1 `adc_subject_init`

- 初始化当前值
- 初始化观察者列表为空

### 6.2 `adc_subject_attach`

- 将观察者注册到 Subject
- 若列表已满，返回失败
- 不允许重复注册同一观察者

### 6.3 `adc_subject_detach`

- 将观察者从 Subject 中移除
- 若观察者不存在，返回失败

### 6.4 `adc_subject_set_value`

- 更新当前 ADC 值
- 打印“ADC 新值”
- 触发通知流程

### 6.5 `adc_subject_notify`

- 遍历观察者列表
- 依次调用每个观察者的 `update`

------

## 7. ADC 数据源要求（必须明确）

ADC 模块必须是唯一数据生产者。
本示例中，不需要实现真实 ADC 驱动，但必须模拟“采集新值”的过程。

推荐方式：

- 在 `main.c` 中准备一个 ADC 采样数组
- 逐个把采样值送入 Subject

例如：

```c
int samples[] = {120, 350, 820, 1023, 600};
```

然后逐次调用：

```c
adc_subject_set_value(&adc, samples[i]);
```

## 8. 必须实现的观察者（至少4个）

每个具体观察者必须单独一个 `.c/.h` 模块，不允许全写在一个文件中。

------

### 8.1 DisplayObserver

职责：

- 接收到新的 ADC 值后，打印显示信息

建议结构：

```c
typedef struct
{
    observer_t base;
} display_observer_t;
```

行为示例：

```text
[Display] ADC value = 350
```

------

### 8.2 AlarmObserver

职责：

- 接收到新的 ADC 值后，判断是否超过阈值
- 若超过阈值，则打印报警信息
- 若未超过，可打印正常或静默处理

建议结构：

```c
typedef struct
{
    observer_t base;
    int threshold;
} alarm_observer_t;
```

行为要求：

- 阈值必须可配置
- 例如阈值设为 `800`

示例输出：

```text
[Alarm] value = 820, threshold = 800, alarm ON
```

------

### 8.3 LoggerObserver

职责：

- 接收到新的 ADC 值后，记录日志

建议结构：

```c
typedef struct
{
    observer_t base;
} logger_observer_t;
```

示例输出：

```text
[Logger] record adc value: 350
```

------

### 8.4 CommObserver

职责：

- 接收到新的 ADC 值后，模拟上报数据

建议结构：

```c
typedef struct
{
    observer_t base;
} comm_observer_t;
```

示例输出：

```text
[Comm] upload adc value: 350
```

## 9. 单生产者多消费者语义（必须在代码中体现）

本示例必须明确体现“单生产者、多消费者”。

必须满足：

- 只有一个 `adc_subject_t`
- 所有观察者都挂接到这个 Subject
- 每次 ADC 值更新，所有观察者都收到通知
- 所有观察者收到的是同一个值
- 任何观察者都不能直接向其他观察者转发数据

禁止出现：

```c
display_update(...);
alarm_check(...);
logger_record(...);
comm_upload(...);
```

由 `main` 顺序手工调用。
这些动作必须由 Subject 的 `notify` 统一触发。

为了体现观察者模式的动态性，建议演示“取消订阅”。

## 14. 禁止事项（非常重要）

AI 生成代码时必须避免以下问题：

### 14.1 禁止在 main 中直接调用各消费者逻辑

错误示例：

```c
display_show(value);
alarm_check(value);
logger_record(value);
comm_upload(value);
```

这不是观察者模式。

------

### 14.2 禁止让 Subject 决定业务联动

Subject 只负责“通知”。
例如 Subject 不能写：

```c
if (value > 800) {
    buzzer_on();
}
```

这是观察者自己的职责，不是 Subject 的职责。

------

### 14.3 禁止观察者之间互相调用

例如：

- Display 不能调用 Logger
- Alarm 不能调用 Comm
- Logger 不能调用 Display

------

### 14.4 禁止只实现一个观察者

必须至少实现 4 个不同观察者。

------

### 14.5 禁止省略 attach/detach

必须具备注册和取消注册能力。
