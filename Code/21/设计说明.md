## 1. 任务目标（必须满足）

实现一个基于 C 语言的解释器模式示例，用于解释一组极简语句。
该解释器只支持：

- 变量创建
- 变量修改
- 变量查看
- 变量删除
- 加法表达式
- 减法表达式

必须体现：

- 存在一组**固定语法规则**
- 存在**上下文对象（变量表）**
- 存在**抽象表达式接口**
- 不同语句或表达式由不同解释对象执行
- 解释器按语法解释输入，而不是写成命令分发表

------

## 2. 支持的语言范围（必须严格限制）

只支持以下四类语句。

### 2.1 赋值语句

格式：

```text
IDENT = expr
```

示例：

```text
a = 10
b = a + 3
c = b - 2
```

语义：

- 如果变量不存在，则创建变量
- 如果变量已存在，则修改变量值

说明：

> 本示例中“创建变量”不单独设计语法，统一通过赋值语句完成。
> 即：首次赋值表示创建，再次赋值表示修改。

------

### 2.2 查看语句

格式：

```text
PRINT IDENT
```

示例：

```text
PRINT a
PRINT b
```

语义：

- 输出变量名和值
- 若变量不存在，输出错误提示

------

### 2.3 删除语句

格式：

```text
DEL IDENT
```

示例：

```text
DEL a
DEL b
```

语义：

- 若变量存在，则删除
- 若变量不存在，输出错误提示

------

### 2.4 表达式语句

格式：

```text
expr
```

示例：

```text
a + b
a - 3
10 + 2
b - a
```

语义：

- 计算表达式结果
- 输出结果
- 不保存到变量表

------

## 3. 表达式范围（必须严格限制）

只支持以下表达式形式：

```text
expr ::= value
       | value '+' value
       | value '-' value
```

其中：

```text
value ::= NUMBER | IDENT
```

限制：

- 只支持**一个二元运算**
- 不支持括号
- 不支持乘除
- 不支持连续表达式，如 `a + b - c`
- 不支持函数
- 不支持字符串
- 不支持浮点数

合法示例：

```text
10
a
a + 3
a - b
```

非法示例：

```text
a + b - c
(a + b)
a * b
```

------

## 4. 总体实现要求（必须满足）

该示例必须是一个**解释器**，不是一个 shell，也不是一个命令分发器。

必须满足：

- 主程序准备一个脚本字符串数组
- 解释器逐条解释执行
- 不实现交互式命令行提示符
- 不实现 while(读取用户输入) 的 REPL 结构
- 不写成 `if (strcmp("PRINT")) ... else if ...` 的纯命令分发器风格

可以有少量语句类型判断，但核心求值必须通过“表达式对象 + interpret 接口”体现。

------

## 5. 上下文对象（必须这样设计）

必须定义变量上下文 `context_t`，用于保存变量表。

推荐结构：

```c
#define MAX_VARS 16
#define MAX_NAME_LEN 32

typedef struct
{
    char name[MAX_NAME_LEN];
    int value;
    int used;
} var_entry_t;

typedef struct
{
    var_entry_t vars[MAX_VARS];
} context_t;
```

要求：

- 使用**固定数组**
- 不使用链表
- 不使用动态扩容
- 不用哈希表

------

## 6. 内存管理约束（非常重要）

本示例的变量表**不得使用动态内存分配**。

也就是说：

- 创建变量时，只能在固定数组中找空槽位
- 删除变量时，只能清空槽位
- 不能为变量节点 `malloc`
- 不能因为变量创建/删除引入内存泄露风险

说明：

> 解释器中的表达式对象可以按需动态分配并在执行后释放；
> 但变量表本身必须使用固定数组实现。

------

## 7. 上下文接口（必须提供）

至少实现以下接口：

```c
void context_init(context_t *ctx);

int context_set_var(context_t *ctx, const char *name, int value);
int context_get_var(context_t *ctx, const char *name, int *out_value);
int context_del_var(context_t *ctx, const char *name);
int context_find_var(context_t *ctx, const char *name);
```

语义要求：

### 7.1 `context_set_var`

- 若变量存在，则修改
- 若变量不存在，则创建
- 若变量表满，则返回失败

### 7.2 `context_get_var`

- 若存在，返回成功并输出值
- 若不存在，返回失败

### 7.3 `context_del_var`

- 若存在，删除并返回成功
- 若不存在，返回失败

------

## 8. 抽象表达式接口（必须存在）

必须定义抽象表达式基类：

```c
typedef struct expression
{
    int (*interpret)(struct expression *self, context_t *ctx, int *out_value);
    void (*destroy)(struct expression *self);
} expression_t;
```

说明：

- `interpret`：解释表达式并输出结果
- `destroy`：释放表达式对象
- `out_value`：返回表达式求值结果

## 10. 语句类型要求（必须实现）

除了表达式对象外，还必须支持以下语句解释。

------

### 10.1 AssignStatement

格式：

```text
IDENT = expr
```

语义：

- 先解释右侧表达式
- 再写入变量表
- 若变量不存在则创建
- 若变量存在则修改

建议结构：

```c
typedef struct
{
    char name[MAX_NAME_LEN];
    expression_t *expr;
} assign_statement_t;
```

------

### 10.2 PrintStatement

格式：

```text
PRINT IDENT
```

语义：

- 查询变量表
- 打印变量值
- 若不存在，打印错误信息

------

### 10.3 DeleteStatement

格式：

```text
DEL IDENT
```

语义：

- 从变量表删除变量
- 若不存在，打印错误信息

------

### 10.4 ExpressionStatement

格式：

```text
expr
```

语义：

- 计算表达式结果
- 打印结果
- 不写入变量表

## 11. 解析器要求（必须实现，但保持简单）

必须实现一个简单解析模块，将一行字符串解析成对应语句或表达式对象。

解析范围只覆盖本说明定义的语法，不要扩展。

建议接口：

```c
statement_t *parse_statement(const char *line);
expression_t *parse_expression(const char *text);
```

要求：

- 允许使用 `sscanf`、`strtok`、`strncmp`、`strchr` 等简单方法
- 不要求实现通用词法分析器
- 不要求构建复杂 AST
- 只需支持本示例的有限语法

------

## 12. 语句抽象接口（推荐实现）

建议把“语句”也抽象出来，而不是全部堆在主函数里。

推荐定义：

```c
typedef struct statement
{
    int (*execute)(struct statement *self, context_t *ctx);
    void (*destroy)(struct statement *self);
} statement_t;
```

这样可以统一：

- `AssignStatement`
- `PrintStatement`
- `DeleteStatement`
- `ExpressionStatement`

## 13. 执行流程（必须按此组织）

主程序必须按以下流程组织：

1. 初始化 `context_t`
2. 准备脚本字符串数组
3. 逐条读取脚本行
4. 调用 `parse_statement`
5. 执行语句
6. 释放语句对象
7. 继续下一条

伪代码：

```c
context_init(&ctx);

for each line in scripts
{
    stmt = parse_statement(line);
    if (stmt != NULL)
    {
        stmt->execute(stmt, &ctx);
        stmt->destroy(stmt);
    }
}
```

## 16. 禁止事项（非常重要）

AI 生成代码时必须避免以下问题：

### 16.1 不要做成交互式 shell

禁止实现：

```c
while (fgets(...))
```

作为主流程。

### 16.2 不要做成单纯命令分发器

禁止把全部行为写成：

```c
if (strncmp(line, "PRINT", 5) == 0) ...
else if (strncmp(line, "DEL", 3) == 0) ...
else if (strchr(line, '=') != NULL) ...
```

然后内部直接算完。
允许用这些手段辅助识别语句类型，但**表达式求值**必须通过表达式对象完成。

### 16.3 不要把所有逻辑写进 main.c

必须拆分模块。

### 16.4 不要给变量表使用动态内存

变量表必须固定容量。

### 16.5 不要支持超出说明范围的语法

不要擅自添加：

- 乘除法
- 括号
- 浮点数
- 多级表达式
- 函数调用
- 交互模式
