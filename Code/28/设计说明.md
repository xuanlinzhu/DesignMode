## 1. 任务目标（必须满足）

实现一个基于 C 语言的模板方法模式示例，用于模拟工业仪表的测量处理流程。

本示例必须体现：

- 存在一个**固定的测量流程骨架**
- 不同测量模式共享同一流程
- 不同测量模式只在某些步骤上实现不同逻辑
- 整体流程顺序不能被子类随意改变
- 通过模板方法体现“流程复用 + 步骤差异化”

------

## 2. 核心场景（必须按此实现）

本示例模拟一个工业仪表的数据处理过程。
无论是哪种测量模式，系统都必须按照以下固定流程执行：

```text
采集原始数据
→ 数据预处理
→ 数据滤波
→ 数据校准
→ 工程量计算
→ 输出结果
```

这个流程顺序必须固定，不能改变。

系统至少支持以下 3 种测量模式：

- **普通测量模式（Normal）**
- **快速测量模式（Fast）**
- **高精度测量模式（Precise）**

这些模式共享同一流程，但每个步骤的具体实现不同。

------

## 3. 模式目标（必须体现）

本示例必须明确体现模板方法模式，而不是普通函数调用组合。

必须体现：

- 抽象基类定义完整流程
- 具体子类实现各步骤
- 主流程由基类统一调度
- 子类不能修改流程顺序
- 差异点体现在步骤实现上，而不是体现在主流程分支判断上

------

## 4. 流程骨架（必须固定）

模板方法必须定义一个固定流程函数，例如：

```c
void measurement_process(measurement_processor_t *self);
```

其内部执行顺序必须严格如下：

```text
1. acquire_data()
2. preprocess_data()
3. filter_data()
4. calibrate_data()
5. compute_result()
6. output_result()
```

说明：

- 这 6 个步骤一个都不能少
- 调用顺序不能变
- 子类不能跳过或重排这些步骤
- 主流程逻辑只能写在模板函数里

------

## 5. 抽象基类（必须存在）

必须定义抽象测量处理器，例如：

```c
typedef struct measurement_processor measurement_processor_t;
```

建议结构：

```c
typedef struct measurement_processor
{
    const char *name;

    int raw_value;
    int processed_value;
    int result_value;

    void (*acquire_data)(struct measurement_processor *self);
    void (*preprocess_data)(struct measurement_processor *self);
    void (*filter_data)(struct measurement_processor *self);
    void (*calibrate_data)(struct measurement_processor *self);
    void (*compute_result)(struct measurement_processor *self);
    void (*output_result)(struct measurement_processor *self);
} measurement_processor_t;
```

说明：

- `name`：模式名称
- `raw_value`：原始采样值
- `processed_value`：处理中间值
- `result_value`：最终工程量结果
- 所有步骤必须通过函数指针实现

------

## 6. 模板方法接口（必须提供）

必须至少提供以下接口：

```c
void measurement_process(measurement_processor_t *self);
```

行为要求：

- 打印当前模式名称
- 严格按固定流程调用各步骤
- 每个步骤调用前后建议打印日志
- 最终输出结果

------

## 7. 具体模式（必须至少实现3种）

必须实现以下 3 种具体处理器：

- `normal_processor_t`
- `fast_processor_t`
- `precise_processor_t`

每种模式都必须实现完整的 6 个步骤，不能省略。

------

## 8. 各模式语义要求（必须严格实现）

------

### 8.1 Normal 模式

语义：

- 用于普通测量场景
- 兼顾稳定性与实时性

步骤要求：

#### `acquire_data`

- 模拟获得一个原始 ADC 值
- 可直接从预设值中读取，例如 `1000`

#### `preprocess_data`

- 对原始值做简单处理，例如去除偏移 10

#### `filter_data`

- 做基础平滑处理，例如：
  - `processed_value = processed_value - 2`

#### `calibrate_data`

- 做简单线性校准，例如：
  - `processed_value = processed_value + 5`

#### `compute_result`

- 将处理值转换为工程量，例如：
  - `result_value = processed_value / 10`

#### `output_result`

- 打印最终结果

------

### 8.2 Fast 模式

语义：

- 用于快速响应场景
- 强调响应速度
- 尽量减少处理步骤复杂度

步骤要求：

#### `acquire_data`

- 获取原始值，例如 `1000`

#### `preprocess_data`

- 做最简单预处理，例如不变或只减小偏移

#### `filter_data`

- 不做复杂滤波，直接透传

#### `calibrate_data`

- 做最简单校准

#### `compute_result`

- 与普通模式类似，但可更直接

#### `output_result`

- 打印最终结果

说明：

- Fast 模式虽然“处理简单”，但仍然必须走完整个模板流程
- 不允许直接绕过某些步骤不调用

------

### 8.3 Precise 模式

语义：

- 用于高精度测量场景
- 强调稳定性和精度

步骤要求：

#### `acquire_data`

- 获取原始值，例如 `1000`

#### `preprocess_data`

- 做更细致预处理，例如减去更精确的偏移

#### `filter_data`

- 做更强的平滑处理，例如多减一点模拟稳定化效果

#### `calibrate_data`

- 做更精细校准，例如增加更多修正量

#### `compute_result`

- 模拟更精细的工程量换算

#### `output_result`

- 打印最终结果

------

## 10. 输入数据要求（建议固定）

为了让不同模式结果可对比，建议三种模式使用同一个原始输入值，例如：

```c
1000
```

这样可以明显看出：

- Normal 的处理结果
- Fast 的处理结果
- Precise 的处理结果

都来自同一测量流程，但步骤实现不同。

------

## 11. 日志输出要求（必须有）

必须通过日志清楚体现：

- 当前处理模式
- 当前执行到哪个步骤
- 每一步处理后的值
- 最终结果

建议输出风格：

```text
[Process] mode = NORMAL
[Step] acquire_data      -> raw = 1000
[Step] preprocess_data   -> processed = 990
[Step] filter_data       -> processed = 988
[Step] calibrate_data    -> processed = 993
[Step] compute_result    -> result = 99
[Step] output_result     -> final result = 99
```

Fast / Precise 也必须有类似日志。

重点是要从日志中明确看出：

- 三种模式执行的是同一个流程
- 只是每一步实现不同

------

## 13. 核心设计约束（非常重要）

------

### 13.1 禁止在 main 中展开流程

错误示例：

```c
proc.acquire_data(...);
proc.preprocess_data(...);
proc.filter_data(...);
...
```

正确方式必须是：

```c
measurement_process(&proc.base);
```

------

### 13.2 禁止在模板函数中按模式写 if/else

错误示例：

```c
if (mode == NORMAL) ...
else if (mode == FAST) ...
```

模板函数只能调用抽象步骤接口，不能自己判断模式。

------

### 13.3 禁止让子类修改流程顺序

不允许在具体模式里重新定义主流程。

流程只能由基类模板函数统一决定。

------

### 13.4 禁止省略步骤

即使某种模式处理较简单，也必须实现全部步骤函数。

例如 Fast 模式不能直接没有 `filter_data`，
而应该实现一个“简单滤波 / 直接透传”的版本。

------

### 13.5 禁止把所有逻辑写进一个大函数

必须拆分为：

- 抽象处理器
- 模板函数
- 具体处理器实现

------
