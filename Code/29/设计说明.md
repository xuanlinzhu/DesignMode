## 1. 任务目标（必须满足）

实现一个基于 C 语言的访问者模式示例，用于模拟：

> **对一组固定类型的仪器模块（温度传感器、压力传感器、电机模块）执行不同操作（信息显示、自检诊断）。**

系统必须体现：

- 模块类型是固定的（Element）
- 操作是可扩展的（Visitor）
- 新增操作不修改模块结构
- 使用访问者模式实现“操作分离”

------

## 2. 核心场景（必须按此实现）

系统中存在多个设备模块：

### 元素类型（固定）

- 温度传感器（TempSensor）
- 压力传感器（PressureSensor）
- 电机模块（Motor）

这些模块：

- 类型稳定
- 不频繁增加新类型
- 每个模块有自己的属性

------

系统需要支持多种操作：

### 操作类型（可扩展）

- 信息显示（InfoVisitor）
- 自检诊断（SelfTestVisitor）

未来还可能增加：

- 导出配置
- 维护检查

------

## 3. 模式目标（必须体现）

本示例必须体现访问者模式核心思想：

- 操作与数据结构分离
- 不同元素对同一操作有不同实现
- 新增操作时不修改元素结构
- 使用双分派（double dispatch）

------

## 4. 元素接口（必须存在）

必须定义抽象元素接口：

```c
typedef struct visitor visitor_t;

typedef struct element
{
    void (*accept)(struct element *self, visitor_t *visitor);
} element_t;
```

说明：

- 所有具体元素必须实现 `accept`
- `accept` 负责触发访问者

------

## 5. 具体元素（必须实现3种）

------

### 5.1 温度传感器

```c
typedef struct
{
    element_t base;
    int temperature;
} temp_sensor_t;
```

------

### 5.2 压力传感器

```c
typedef struct
{
    element_t base;
    int pressure;
} pressure_sensor_t;
```

------

### 5.3 电机模块

```c
typedef struct
{
    element_t base;
    int speed;
} motor_t;
```

------

## 6. Visitor接口（必须存在）

必须定义访问者接口：

```c
typedef struct visitor
{
    void (*visit_temp)(struct visitor *self, temp_sensor_t *elem);
    void (*visit_pressure)(struct visitor *self, pressure_sensor_t *elem);
    void (*visit_motor)(struct visitor *self, motor_t *elem);
} visitor_t;
```

说明：

- 每种元素必须有对应 visit 函数
- 不允许用通用 visit(void*) 代替
- 必须体现“针对不同类型的处理”

------

## 7. 双分派机制（必须实现）

每个元素的 `accept` 必须实现如下逻辑：

------

### TempSensor

```c
void temp_accept(element_t *self, visitor_t *visitor)
{
    visitor->visit_temp(visitor, (temp_sensor_t *)self);
}
```

------

### PressureSensor

```c
visitor->visit_pressure(...)
```

------

### Motor

```c
visitor->visit_motor(...)
```

------

说明：

- 必须通过 accept → visitor → visit_xxx
- 不允许绕过 accept 直接调用 visitor

------

## 8. 具体访问者（必须至少实现2种）

------

### 8.1 InfoVisitor（信息显示）

结构：

```c
typedef struct
{
    visitor_t base;
} info_visitor_t;
```

行为：

- 温度传感器：打印温度
- 压力传感器：打印压力
- 电机：打印转速

示例输出：

```text
[Info] TempSensor: 25
[Info] PressureSensor: 100
[Info] Motor speed: 1500
```

------

### 8.2 SelfTestVisitor（自检）

结构：

```c
typedef struct
{
    visitor_t base;
} selftest_visitor_t;
```

行为：

- 温度传感器：判断温度范围
- 压力传感器：判断压力范围
- 电机：判断转速是否正常

示例输出：

```text
[SelfTest] TempSensor OK
[SelfTest] PressureSensor OK
[SelfTest] Motor OK
```

## 10. 客户端逻辑（必须这样写）

遍历元素集合：

```c
for (i = 0; i < count; i++)
```

- 客户端不关心元素具体类型
- 不允许写类型判断

## 13. 核心设计约束（非常重要）

------

### 13.1 禁止用 if/else 判断元素类型

错误示例：

```c
if (type == TEMP) ...
else if (type == MOTOR) ...
```

------

### 13.2 禁止在 visitor 中写 void* 强转

必须使用明确接口：

```c
visit_temp(...)
visit_motor(...)
```

------

### 13.3 禁止绕过 accept 调用 visit

必须：

```c
element->accept(...)
```

------

### 13.4 禁止在元素中实现操作逻辑

元素只负责数据，不负责：

- 显示
- 自检

------

### 13.5 禁止把所有逻辑写成普通函数调用

必须体现：

- accept
- visitor
- visit_xxx

------

## 14. 内存与实现要求

- 不使用动态内存（推荐）
- 使用静态对象
- 不涉及线程

```c
    void (*accept)(struct element *, struct visitor *);

typedef struct visitor
{
    void (*visit_temp)(struct visitor *, temp_sensor_t *);
    void (*visit_pressure)(struct visitor *, pressure_sensor_t *);
    void (*visit_motor)(struct visitor *, motor_t *);
} visitor_t;
```
