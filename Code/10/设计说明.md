# 最小设计说明：Log 单例（PC console示例）+ 预留标准 Driver 接口

## 1) 设计意图（对应 GoF Singleton）

### Intent（嵌入式/系统角度表达）

保证系统中日志服务的**控制块唯一**，并通过**唯一访问入口**对外提供服务；同时将输出通道抽象为 driver 接口，避免 Core 与具体输出介质耦合。

### 单例概念映射（关键点）

| GoF 概念              | 本设计对应                                                   |
| --------------------- | ------------------------------------------------------------ |
| 唯一实例              | `glog.c` 内部 `static glog_core_t g_core;`                   |
| 私有构造/禁止外部创建 | `glog_core_t` 结构体只在 `glog.c` 定义，头文件不暴露         |
| Instance() 全局访问点 | `glog_init()` + `glog_print()`（内部通过 `g_core` 工作）     |
| 受控初始化            | `glog_init()` 幂等 + 线程安全                                |
| 生命周期              | 与进程同寿命（默认不需要显式销毁；提供 `glog_close()` 释放资源） |

## 3) 分层与职责

### 3.1 LogCore（`glog.c`）

负责：

- level 过滤（`level > threshold` 丢弃）
- 生成最终文本（时间、file:line 由 ex_message_level 控制）
- 更新 `record_level`（记录出现过的最严重等级）
- 并发保护（PC：pthread mutex）
- 调用 driver 的 `write()` 完成输出

### 3.2 Driver（`log_driver_console.c`）

负责：

- 把 Core 交付的 `log_record_t` 落地输出到终端
- 是否加颜色（ANSI color）由 driver 决定（Core 输出始终为 plain text）
- flush（`fflush`）

**原则**：Core 不直接调用 `printf/write/syslog`，只通过 driver ops。

------

## 4) 对外 API（`glog.h`）

### 4.1 配置结构 `glog_config_t`（最小字段）

- `int level_threshold;`
- `int ex_message_level;` 取值 0/1/2
  - 0：只输出用户 msg
  - 1：`[time] msg`
  - 2：`[time] [file:line] msg`
- `int color_enable;`（仅 console driver 使用）

### 4.2 核心函数（单例访问点）

- `int glog_init(const glog_config_t* cfg);`
  - 幂等：重复调用返回成功
  - 线程安全：多线程并发 init 也只初始化一次
- `void glog_close(void);`（幂等）
- `void glog_print(int level, const char* file, int line, const char* fmt, ...);`
- `int glog_get_record_level(void);`
- `void glog_reset_record_level(void);`

### 4.3 宏（必须）

- `GLOG_PRINT(level, fmt, ...)` → 调用 `glog_print(level, __FILE__, __LINE__, fmt, ...)`
- 禁止宏中直接输出（禁止 `printf/syslog`），保证“唯一访问路径”与分层不被绕开

------

## 5) 标准 Driver 接口（`log_driver.h`）—— 只定义，不额外占位文件

### 5.1 `log_record_t`（Core→Driver）

必须包含：

- `int level;`
- `const char* text; size_t text_len;`（最终文本，plain）
- `const char* file; int line;`（可选字段，便于 console backend 做 ex=2 或诊断；但 Core 已可写入 text）
- `uint64_t ts_ms;`（可选；后续 flash 可能用）

### 5.2 `log_driver_ops_t`

- `int (*open)(void* ctx, const glog_config_t* core_cfg);`
- `int (*write)(void* ctx, const log_record_t* rec);`
- `int (*flush)(void* ctx);`（可为 NULL）
- `void (*close)(void* ctx);`

### 5.3 `log_driver_t`

- `const char* name;`
- `const log_driver_ops_t* ops;`
- `void* ctx;`
- `int enabled;`

> 预留对接 syslog/uart/spiflash 的方式：只要实现一个新的 driver（一个 `.c` 文件）填充 `ops`，然后在 `glog_init()` 注册即可。Core 不需要任何改动。

------

## 6) “中间操作”如何体现单例（严格对齐概念）

把运行路径写清楚（这对生成器/验收很关键）：

### 6.1 `glog_init()`：单例的“受控构造”

1. 进入全局 mutex（确保并发 init 不重复）
2. 检查 `g_core.inited`
   - 已 init → 直接返回成功（不重复构造）
3. 写入默认配置，再覆盖用户 cfg
4. 绑定并打开 driver（本版本固定绑定 console driver）
5. `g_core.inited = 1`
6. 退出 mutex

> 这一步对应 GoF 的：**实例创建与初始化被集中控制**。

### 6.2 `glog_print()`：单例的“唯一服务入口”

1. 进入 mutex（保证全局状态一致、输出不交错）
2. 先更新 `record_level`
3. 若未 init → 返回（但 record_level 已体现“全局状态”）
4. 若 level 被过滤 → 返回
5. Core 格式化 `log_record_t.text`
6. 调用 `console_driver.write()`
7. 退出 mutex

> 这一步对应 GoF 的：**通过唯一实例提供服务，外部无法绕开实例直接操作资源**（因为宏禁止直接输出）。

------

## 7) PC 示例 driver：console（`log_driver_console.c`）

- 输出流选择：
  - `level <= ERR` → `stderr`
  - 其他 → `stdout`
- 颜色：
  - `core_cfg->color_enable==1` 且输出是 tty → 加 ANSI 颜色
  - 颜色映射可沿用你现在的 level→color 逻辑
- flush：`fflush`

------

## 8) demo（`demo.c`）验收点

- `glog_init()` 一次初始化，多次调用不重复初始化
- 输出 ex_message_level=0/1/2 的效果
- 多线程并发打印（可选）不交错（至少不破坏行级完整性）
- `record_level` 获取与 reset 正常

------

## 9) 给代码生成器的最短约束（可直接粘贴）

- 仅生成：`glog.h log_driver.h glog.c log_driver_console.c demo.c` + 构建文件
- `glog.c` 内必须存在 `static` 单例控制块，结构体不对外暴露
- `glog_init/glog_print/glog_close` 必须幂等/线程安全
- 必须通过 driver ops 输出，宏禁止直接输出
- 只实现 console driver；syslog/uart/spiflash 只通过接口预留（不生成占位文件）
