# Builder 模式示例设计说明（07）

## 1. 目标

本示例将 `Source/07-3.2[生成器].md` 的协议场景落地为可运行 C 代码，演示：

- 将报文构造流程（算法）与报文具体结构（表示）分离。
- 用同一构建顺序生成不同协议版本（普通帧、带安全与扩展的帧）。
- 在嵌入式约束下使用固定缓冲区，不依赖动态内存。

## 2. 角色映射

- `Builder`：`FrameBuilder`（定义并承载各步骤函数指针）。
- `ConcreteBuilder`：
  - `init_v1_builder()`：普通帧，无安全块、无扩展头、CRC8。
  - `init_secure_extended_builder()`：带安全块、扩展头、CRC16。
- `Director`：`FrameDirector` + `construct_frame()`，统一调度构造顺序。
- `Product`：`FrameProduct`，输出最终字节流与长度。

## 3. 文件结构

- `Code/07/protocol_builder.h`：类型、状态机、接口声明。
- `Code/07/protocol_builder.c`：Builder/Director 具体实现与 CRC 算法。
- `Code/07/main.c`：客户端演示，构建两种协议帧并打印十六进制结果。
- `Code/07/Makefile`：编译、清理、运行。

## 4. 构建顺序与依赖

Director 固定步骤：

1. `reset`
2. `build_payload`
3. `build_sub_header`（依赖 payload 长度）
4. `build_security`（可选，依赖 payload）
5. `build_ext_header`（可选）
6. `build_header`（依赖前述长度）
7. `build_crc`（依赖整帧）

该顺序与最终字节布局可不同，但可保证字段依赖正确。

## 5. 关键实现点

- 固定容量缓冲区：`FRAME_BUFFER_CAPACITY`、`MAX_PAYLOAD_CAPACITY`。
- 追加写保护：`append_bytes()` 防止越界。
- 状态机约束：每一步检查 `FrameBuildState`，防止非法顺序。
- 版本差异只体现在 ConcreteBuilder 步骤函数绑定，Director 不变。

## 6. 运行方式

在 `Code/07` 目录执行：

```bash
make
make run
```

输出会展示两帧报文（普通版本与安全扩展版本）的十六进制字节流。
