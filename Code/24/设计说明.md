## 1. 任务目标（必须满足）

实现一个基于 C 语言的备忘录模式示例，用于模拟仪器参数配置的状态保存与恢复。

本示例必须同时支持两类备忘录场景：

### 1.1 调试模式前参数备忘录

系统进入调试模式前，必须先保存当前运行参数快照。
退出调试模式时，可以恢复进入调试模式之前的参数状态。

### 1.2 系统默认参数备忘录

系统初始化后，必须保存一份“默认参数快照”。
当发生恢复默认参数操作时，可以直接恢复到这份默认参数状态。

------

## 2. 模式目标（必须体现）

本示例必须明确体现备忘录模式的三个角色：

- **Originator（发起人）**：当前参数对象，负责创建和恢复备忘录
- **Memento（备忘录）**：保存参数快照
- **Caretaker（管理者）**：负责保存备忘录，但不直接操作参数细节

必须体现：

- 参数对象对外不暴露内部状态细节
- 外部不能直接修改备忘录内部内容
- 备忘录只用于保存和恢复状态
- 不允许把“备份功能”写成简单的几个全局变量复制

------

## 3. 核心场景（必须按此实现）

系统维护一组仪器参数，例如：

- 增益 `gain`
- 偏移 `offset`
- 阈值 `threshold`
- 工作模式 `mode`

要求同时支持以下两个方向。

------

### 3.1 方向一：进入调试模式前的参数备忘录

业务语义：

- 系统在正常运行时，存在一组当前参数
- 当用户进入调试模式前，系统必须先保存一份“调试前参数快照”
- 在调试模式下，用户可以修改参数
- 当用户退出调试模式并选择恢复时，系统应恢复到进入调试模式之前的参数状态

必须体现：

- “调试前备忘录”是一个独立用途的快照
- 它表示“进入调试模式前的现场参数”
- 它不是默认参数，也不是历史撤销栈

------

### 3.2 方向二：系统默认参数备忘录

业务语义：

- 系统上电初始化后，存在一组默认参数
- 系统必须保存一份“默认参数快照”
- 无论当前参数如何被修改，用户都可以执行“恢复默认参数”
- 恢复默认参数时，系统应恢复到初始化时保存的默认参数状态

必须体现：

- “默认参数备忘录”长期存在
- 它表示“系统标准出厂/默认配置”
- 它与“调试前备忘录”用途不同，不能混用

------

## 4. 数据对象（Originator，必须存在）

必须定义一个参数对象，例如：

```c
typedef struct
{
    int gain;
    int offset;
    int threshold;
    int mode;
} instrument_param_t;
```

说明：

- `instrument_param_t` 是 Originator
- 它代表系统当前可运行的一组完整参数状态
- 所有快照都必须来自这个对象
- 所有恢复都必须写回这个对象

------

## 5. 备忘录对象（Memento，必须存在）

必须定义参数备忘录对象，例如：

```c
typedef struct
{
    int gain;
    int offset;
    int threshold;
    int mode;
} param_memento_t;
```

说明：

- 备忘录保存的是参数对象的一份完整快照
- 必须保存整个状态，而不是零散字段
- 外部管理者只负责“保存这个快照”和“交回这个快照”
- 外部管理者不负责理解其中具体字段意义

------

## 6. 管理者对象（Caretaker，必须拆成两个方向）

本示例必须明确区分两类管理者用途。

------

### 6.1 调试模式参数管理者

必须定义一个专门保存“进入调试模式前参数”的管理者，例如：

```c
typedef struct
{
    param_memento_t debug_snapshot;
    int has_debug_snapshot;
} debug_param_caretaker_t;
```

职责：

- 保存进入调试模式前的参数快照
- 判断当前是否存在有效调试前快照
- 在需要时提供该快照用于恢复

说明：

- 这里只保存一份快照
- 不实现多级撤销栈
- 不允许和默认参数快照共用同一个字段表示

------

### 6.2 默认参数管理者

必须定义一个专门保存“系统默认参数”的管理者，例如：

```c
typedef struct
{
    param_memento_t default_snapshot;
    int has_default_snapshot;
} default_param_caretaker_t;
```

职责：

- 保存系统初始化后的默认参数快照
- 在恢复默认参数时提供该快照

说明：

- 默认参数快照通常在初始化后保存一次
- 之后长期存在
- 不受调试模式进入/退出影响

------

## 7. Originator接口（必须提供）

参数对象必须提供以下接口：

```c
void instrument_param_init(instrument_param_t *self, int gain, int offset, int threshold, int mode);
void instrument_param_print(const instrument_param_t *self);

param_memento_t instrument_param_create_memento(const instrument_param_t *self);
void instrument_param_restore_memento(instrument_param_t *self, const param_memento_t *memento);
```

语义要求：

### 7.1 `instrument_param_create_memento`

- 从当前参数对象创建完整快照
- 返回一个 `param_memento_t`

### 7.2 `instrument_param_restore_memento`

- 将备忘录中的状态完整恢复到当前参数对象
- 必须覆盖所有字段

------

## 8. 参数修改接口（必须存在）

必须提供若干参数修改接口，例如：

```c
void instrument_param_set_gain(instrument_param_t *self, int gain);
void instrument_param_set_offset(instrument_param_t *self, int offset);
void instrument_param_set_threshold(instrument_param_t *self, int threshold);
void instrument_param_set_mode(instrument_param_t *self, int mode);
```

说明：

- 这些接口用于模拟调试模式下参数被修改
- 必须通过日志体现修改前后状态变化

------

## 9. 调试模式备忘录接口（必须提供）

必须提供专门的调试快照保存/恢复接口，例如：

```c
void debug_caretaker_save(debug_param_caretaker_t *self, param_memento_t memento);
int debug_caretaker_has_snapshot(const debug_param_caretaker_t *self);
const param_memento_t *debug_caretaker_get(const debug_param_caretaker_t *self);
void debug_caretaker_clear(debug_param_caretaker_t *self);
```

语义要求：

### 9.1 保存调试前快照

- 进入调试模式前调用
- 用当前参数创建快照并交给调试管理者保存

### 9.2 恢复调试前参数

- 退出调试模式且选择恢复时调用
- 若存在调试快照，则恢复
- 恢复完成后可以清除该快照

说明：

- 恢复后清除是推荐实现
- 表示这份快照只服务一次调试会话

------

## 10. 默认参数备忘录接口（必须提供）

必须提供默认快照保存/恢复接口，例如：

```c
void default_caretaker_save(default_param_caretaker_t *self, param_memento_t memento);
int default_caretaker_has_snapshot(const default_param_caretaker_t *self);
const param_memento_t *default_caretaker_get(const default_param_caretaker_t *self);
```

语义要求：

### 10.1 保存默认参数

- 系统初始化完成后调用一次
- 将初始参数快照保存为默认参数

### 10.2 恢复默认参数

- 用户触发“恢复默认参数”时调用
- 若存在默认快照，则恢复当前参数

说明：

- 默认快照不能因调试流程被清除
- 默认快照生命周期长于调试快照

------

## 11. 两类备忘录的区别（必须在代码语义中体现）

必须清楚区分这两类备忘录：

| 类型             | 作用                   | 生命周期 | 典型触发       |
| ---------------- | ---------------------- | -------- | -------------- |
| 调试前参数备忘录 | 退出调试时恢复现场参数 | 短期     | 进入调试模式前 |
| 默认参数备忘录   | 恢复系统默认参数       | 长期     | 系统初始化后   |

禁止：

- 用一个变量既表示调试快照，又表示默认快照
- 在代码中混淆“恢复调试前参数”和“恢复默认参数”
- 用统一 `backup` 命名模糊两类语义

建议命名明确区分：

- `debug_snapshot`
- `default_snapshot`

------

- 恢复的是哪一种备忘录
- 修改参数后的变化

建议输出风格：


## 13. main函数要求（必须覆盖两个方向）

主函数必须至少演示以下两个完整场景。

------

### 场景1：进入调试模式前参数备忘录

执行流程必须包括：

1. 初始化当前参数
2. 保存默认参数快照
3. 进入调试模式前保存调试快照
4. 修改多个参数
5. 打印当前参数
6. 恢复调试快照
7. 再次打印参数，证明已恢复到调试前状态

------

### 场景2：恢复系统默认参数

执行流程必须包括：

1. 在当前参数基础上再次修改参数
2. 打印当前参数
3. 恢复默认参数快照
4. 打印参数，证明恢复到系统初始默认状态

------

## 14. 禁止事项（非常重要）

AI 生成代码时必须避免以下问题：

### 14.1 禁止把备忘录写成几个散乱备份变量

错误示例：

```c
int backup_gain;
int backup_offset;
```

必须使用明确的 `param_memento_t`。

------

### 14.2 禁止让管理者直接修改参数对象

管理者只能保存和提供备忘录。
恢复动作必须由 Originator 完成。

错误方向：

```c
caretaker_restore(...)
{
    param->gain = ...
}
```

这是不允许的。

------

### 14.3 禁止混淆两种备忘录语义

不能用同一个 `backup` 同时表示：

- 调试前快照
- 默认参数快照

------

### 14.4 禁止把“恢复默认参数”和“退出调试恢复”写成同一件事

这两个流程必须分别演示，分别命名。

------

### 14.5 禁止省略 Originator 的 create/restore 接口

必须明确存在：

- `create_memento`
- `restore_memento`

否则备忘录模式不完整。

------

## 15. 内存管理要求

本示例不要求动态内存分配。
推荐全部使用栈对象或普通结构体成员实现。

说明：

- `param_memento_t` 直接按值拷贝即可
- `debug_param_caretaker_t` 和 `default_param_caretaker_t` 直接持有备忘录对象
- 本示例不实现多级历史栈
- 本示例不涉及堆内存，因此不引入内存泄露问题
