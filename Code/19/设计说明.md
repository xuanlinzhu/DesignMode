## 1. 任务目标（必须满足）

实现一个基于 C 语言的责任链模式示例，用于模拟：

> **TCP 连接在建立前，经过多个安全检查节点逐级传递的过程**

必须体现：

- 请求对象在多个节点之间**传递**
- 每个节点只负责**一个独立检查**
- 节点可以决定：
  - 继续传递
  - 拒绝并终止
- 客户端只调用**链入口**
- 不允许写成一组 `if/else` 顺序调用

------

## 2. 核心行为（强约束）

实现的执行流程必须满足：

```text
connection_request
    ↓
handler1 -> handler2 -> handler3 -> handler4
    ↓
某节点拒绝 OR 全部通过
```

运行逻辑必须是：

```c
node = head;

while (node != NULL)
{
    result = node->handle(conn);

    if (result == REJECT)
        return REJECT;

    if (result == ACCEPT)
        return ACCEPT;

    node = node->next;
}

return ACCEPT;
```

------

## 3. 返回值定义（必须统一）

禁止使用 bool 或 int 乱写。

必须定义：

```c
typedef enum
{
    CHAIN_CONTINUE = 0,  // 当前节点不终止，继续传递
    CHAIN_REJECT,       // 拒绝，终止链
    CHAIN_ACCEPT        // 直接放行（可选）
} chain_result_t;
```

------

## 4. 数据对象（连接请求）

必须定义一个连接结构体：

```c
typedef struct
{
    int ip;
    int current_conn;
    int max_conn;
    int request_freq;
    int token_valid;
} conn_t;
```

说明：

- `ip`：用于黑名单判断
- `current_conn / max_conn`：连接数限制
- `request_freq`：频率检测
- `token_valid`：认证

------

## 5. Handler接口（必须这样设计）

必须使用函数指针 + next 指针实现链，不允许写成数组遍历版本。

```c
typedef struct handler
{
    chain_result_t (*handle)(struct handler *self, conn_t *conn);
    struct handler *next;
} handler_t;
```

必须提供：

```c
void handler_set_next(handler_t *self, handler_t *next);
```

------

## 6. 必须实现的节点（至少4个）

每个节点必须单独一个 `.c/.h`，不能写在一个文件里。

### 6.1 黑名单检查

```c
chain_result_t blacklist_handle(...)
```

规则：

- 如果 `ip == 0` → REJECT
- 否则 → CONTINUE

------

### 6.2 连接数限制

```c
if (current_conn >= max_conn)
    return REJECT;
```

------

### 6.3 频率限制

```c
if (request_freq > 100)
    return REJECT;
```

------

### 6.4 认证检查

```c
if (token_valid == 0)
    return REJECT;
```

------

## 7. 责任链执行函数（必须存在）

必须提供统一入口：

```c
chain_result_t run_chain(handler_t *head, conn_t *conn);
```

行为：

- 从 head 开始
- 逐节点调用
- 按返回值决定是否继续

必须构造如下链：

```text
blacklist -> conn_limit -> rate_limit -> auth
```

必须测试至少 3 个场景：

------

### 场景1：正常通过


------

### 场景2：中间节点拒绝

例如：

```text

conn_limit → REJECT（终止）
后面节点不会执行
```

必须打印日志证明“后续节点未执行”。

------

### 场景3：第一个节点拒绝

```text
blacklist → REJECT
```

## 9. 日志输出（必须有）

每个节点必须打印：

```text
[RateLimit] skip (不会出现)
```

用于证明：
