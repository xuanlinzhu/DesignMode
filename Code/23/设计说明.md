## 1. 任务目标（必须满足）

实现一个基于 C 语言的中介者模式示例，用于模拟仪器仪表系统中的联动控制。

系统中至少包含以下功能模块：

- 报警模块
- 调试模式模块
- 功能运行模块
- 显示模块
- 蜂鸣器模块
- 状态灯模块

必须体现：

- 各模块**不能直接互相调用**
- 各模块只与**中介者**通信
- 中介者负责统一处理：
  - 报警联动
  - 手动触发报警
  - 报警解除
  - 进入调试模式
  - 退出调试模式
  - 启动运行
  - 停止运行
  - 显示切换
- 中介者内部维护系统状态，并根据状态决定联动行为

------

## 2. 核心场景（必须按此实现）

本示例模拟一个简化的仪器仪表控制系统。
系统存在以下状态与联动：

### 2.1 报警触发

当发生报警时：

- 显示模块切换到报警界面
- 蜂鸣器打开
- 状态灯切换为红色闪烁
- 功能运行模块停止运行
- 系统进入报警状态

------

### 2.2 手动触发报警

必须支持“人工手动触发报警”。

例如：

- 用户按下一个“报警测试”按钮
- 系统主动进入报警联动流程

手动触发报警的联动效果**必须与普通报警一致**：

- 切换报警界面
- 蜂鸣器打开
- 红灯闪烁
- 停止运行

说明：

> “手动触发报警”不是一个独立的设备联动结果，而是一个额外的报警来源。
> 中介者必须统一处理报警来源，而不是让显示、蜂鸣器、状态灯分别判断来源。

------

### 2.3 报警解除

当报警被解除时：

- 蜂鸣器关闭
- 状态灯恢复默认状态
- 显示模块恢复主界面
- 系统清除报警状态
- 运行模块仍保持停止，是否重新启动由外部事件决定

------

### 2.4 进入调试模式

当进入调试模式时：

- 显示模块切换到调试界面
- 状态灯切换为黄色常亮
- 若系统当前处于运行状态，则停止运行
- 系统进入调试模式状态
- 调试模式下不允许启动正常运行流程

------

### 2.5 退出调试模式

当退出调试模式时：

- 显示模块恢复主界面
- 状态灯恢复默认状态（若无报警）
- 系统退出调试模式状态

------

### 2.6 启动运行

当接收到启动运行请求时：

- 若当前**不在报警状态**
- 且当前**不在调试模式**
- 则允许运行模块启动
- 显示模块切换到运行界面
- 状态灯切换为绿色常亮
- 系统进入运行状态

否则：

- 不允许启动
- 输出原因日志

------

### 2.7 停止运行

当接收到停止运行请求时：

- 运行模块停止
- 显示模块恢复主界面（若无报警、无调试）
- 状态灯恢复默认状态（若无报警、无调试）
- 系统退出运行状态

------

## 3. 模式要求（必须满足）

本示例必须明确体现中介者模式，而不是一个普通总控函数堆逻辑。

必须体现：

- 存在一个中介者对象
- 所有 colleague 模块都持有中介者指针
- 各模块发生事件时调用中介者通知接口
- 中介者根据事件和当前系统状态决定联动动作
- 各模块之间不能直接调用彼此方法

------

## 4. 中介者对象（必须存在）

必须定义一个中介者结构体，例如：

```c
typedef struct instrument_mediator instrument_mediator_t;
```

中介者必须承担两个职责：

### 4.1 维护系统状态

至少维护以下状态：

```c
int alarm_active;
int debug_mode;
int running;
```

可选增加：

```c
int manual_alarm_active;
```

但更推荐将“手动触发报警”只作为事件来源，不单独做持久状态。

------

### 4.2 协调联动

中介者根据事件执行如下协调：

- 控制显示模块切换界面
- 控制蜂鸣器开关
- 控制状态灯变化
- 控制运行模块启停

------

## 5. 事件类型（必须统一定义）

必须定义统一事件枚举：

```c
typedef enum
{
    EVENT_ALARM_ON = 0,
    EVENT_ALARM_OFF,
    EVENT_MANUAL_ALARM_ON,
    EVENT_ENTER_DEBUG,
    EVENT_EXIT_DEBUG,
    EVENT_START_RUN,
    EVENT_STOP_RUN
} event_t;
```

说明：

- `EVENT_MANUAL_ALARM_ON` 必须存在
- 手动触发报警必须走中介者统一流程
- 不允许手动报警逻辑绕过中介者直接操作其他模块

------

## 6. 中介者接口（必须提供）

必须提供统一通知接口：

```c
void mediator_notify(instrument_mediator_t *self, void *sender, event_t event);
```

说明：

- `sender` 表示事件来源模块
- `event` 表示事件类型
- 中介者根据 `event` 执行联动规则

------

## 7. Colleague模块（必须存在）

至少实现以下模块：

- `alarm_module_t`
- `debug_module_t`
- `run_module_t`
- `display_module_t`
- `buzzer_module_t`
- `led_module_t`

每个模块都必须持有中介者指针，例如：

```c
typedef struct
{
    instrument_mediator_t *mediator;
} alarm_module_t;
```

禁止：

- `alarm_module_t` 直接持有 `display_module_t *`
- `debug_module_t` 直接持有 `run_module_t *`
- `run_module_t` 直接持有 `led_module_t *`

即：**禁止 colleague 之间直接引用。**

------

## 8. 各模块职责（必须分清）

------

### 8.1 AlarmModule

职责：

- 触发报警事件
- 解除报警事件
- 触发手动报警事件

必须提供：

```c
void alarm_module_trigger(alarm_module_t *self);
void alarm_module_clear(alarm_module_t *self);
void alarm_module_manual_trigger(alarm_module_t *self);
```

行为：

- 这些函数内部只能调用 `mediator_notify`
- 不能直接改显示、蜂鸣器、状态灯、运行模块

------

### 8.2 DebugModule

职责：

- 请求进入调试模式
- 请求退出调试模式

必须提供：

```c
void debug_module_enter(debug_module_t *self);
void debug_module_exit(debug_module_t *self);
```

------

### 8.3 RunModule

职责：

- 启动运行
- 停止运行
- 被中介者真正控制启停

必须区分两类接口：

#### 对外请求接口

由外部触发，只通知中介者：

```c
void run_module_request_start(run_module_t *self);
void run_module_request_stop(run_module_t *self);
```

#### 对内执行接口

由中介者调用，用于真正改变运行状态：

```c
void run_module_start(run_module_t *self);
void run_module_stop(run_module_t *self);
```

说明：

- `request_start/request_stop` 只能通知中介者
- `start/stop` 只能由中介者调用

------

### 8.4 DisplayModule

职责：

- 显示主界面
- 显示报警界面
- 显示调试界面
- 显示运行界面

必须提供：

```c
void display_show_main(display_module_t *self);
void display_show_alarm(display_module_t *self);
void display_show_debug(display_module_t *self);
void display_show_run(display_module_t *self);
```

------

### 8.5 BuzzerModule

职责：

- 开启蜂鸣器
- 关闭蜂鸣器

必须提供：

```c
void buzzer_on(buzzer_module_t *self);
void buzzer_off(buzzer_module_t *self);
```

------

### 8.6 LedModule

职责：

- 设置默认状态
- 设置红灯闪烁
- 设置黄灯常亮
- 设置绿灯常亮

必须提供：

```c
void led_set_default(led_module_t *self);
void led_set_red_blink(led_module_t *self);
void led_set_yellow_on(led_module_t *self);
void led_set_green_on(led_module_t *self);
```

------

## 9. 中介者内部持有的模块引用（必须这样设计）

中介者必须持有所有 colleague 的引用，例如：

```c
struct instrument_mediator
{
    int alarm_active;
    int debug_mode;
    int running;

    alarm_module_t *alarm;
    debug_module_t *debug;
    run_module_t *run;
    display_module_t *display;
    buzzer_module_t *buzzer;
    led_module_t *led;
};
```

说明：

- 联动动作统一由中介者调度这些模块完成
- 各模块本身不直接访问其他模块

------

## 10. 联动规则（必须严格按此实现）

------

### 10.1 EVENT_ALARM_ON

中介者处理流程必须是：

1. 设置 `alarm_active = 1`
2. 若当前 `running == 1`，调用 `run_module_stop`
3. 调用 `display_show_alarm`
4. 调用 `buzzer_on`
5. 调用 `led_set_red_blink`

------

### 10.2 EVENT_MANUAL_ALARM_ON

处理流程必须与 `EVENT_ALARM_ON` 一致。

说明：

- 日志中必须明确这是“manual alarm”
- 但联动效果不能与普通报警分叉成另一套控制逻辑

------

### 10.3 EVENT_ALARM_OFF

中介者处理流程必须是：

1. 设置 `alarm_active = 0`
2. 调用 `buzzer_off`
3. 若当前 `debug_mode == 1`
   - 调用 `display_show_debug`
   - 调用 `led_set_yellow_on`
4. 否则若当前 `running == 1`
   - 调用 `display_show_run`
   - 调用 `led_set_green_on`
5. 否则
   - 调用 `display_show_main`
   - 调用 `led_set_default`

------

### 10.4 EVENT_ENTER_DEBUG

中介者处理流程必须是：

1. 设置 `debug_mode = 1`
2. 若当前 `running == 1`，调用 `run_module_stop`
3. 调用 `display_show_debug`
4. 若当前 `alarm_active == 0`，调用 `led_set_yellow_on`

说明：

- 若当前在报警状态，报警显示和红灯优先级高于调试显示
- 为避免逻辑过于复杂，本示例中可规定：
  - 当报警已激活时，进入调试只更新 `debug_mode` 状态，不覆盖报警界面和红灯
- 这条必须在实现中写清楚日志

------

### 10.5 EVENT_EXIT_DEBUG

中介者处理流程必须是：

1. 设置 `debug_mode = 0`
2. 若当前 `alarm_active == 1`
   - 调用 `display_show_alarm`
   - 调用 `led_set_red_blink`
3. 否则若当前 `running == 1`
   - 调用 `display_show_run`
   - 调用 `led_set_green_on`
4. 否则
   - 调用 `display_show_main`
   - 调用 `led_set_default`

------

### 10.6 EVENT_START_RUN

中介者必须先判断条件：

- 若 `alarm_active == 1`
  - 拒绝启动
  - 打印日志：alarm active
- 若 `debug_mode == 1`
  - 拒绝启动
  - 打印日志：debug mode active
- 否则：
  1. 调用 `run_module_start`
  2. 设置 `running = 1`
  3. 调用 `display_show_run`
  4. 调用 `led_set_green_on`

------

### 10.7 EVENT_STOP_RUN

中介者处理流程必须是：

1. 若 `running == 1`，调用 `run_module_stop`
2. 设置 `running = 0`
3. 若当前 `alarm_active == 1`
   - 调用 `display_show_alarm`
   - 调用 `led_set_red_blink`
4. 否则若当前 `debug_mode == 1`
   - 调用 `display_show_debug`
   - 调用 `led_set_yellow_on`
5. 否则
   - 调用 `display_show_main`
   - 调用 `led_set_default`

------

## 11. 运行状态维护要求（非常重要）

`run_module_start()` 与 `run_module_stop()` 中可以维护模块自身状态，
但中介者中的 `running` 也必须同步维护。

要求：

- `EVENT_START_RUN` 成功后：`running = 1`
- `EVENT_STOP_RUN` 后：`running = 0`
- 报警触发导致停止运行时：`running = 0`
- 进入调试模式导致停止运行时：`running = 0`

------

## 12. 日志输出要求（必须有）

必须通过日志证明：

- 事件由模块发出
- 联动由中介者统一处理
- 模块之间没有直接调用

建议输出风格：

```text
[AlarmModule] trigger alarm
[Mediator] event: ALARM_ON
[Mediator] stop running due to alarm
[RunModule] stop
[Display] show alarm page
[Buzzer] ON
[LED] RED BLINK
```

手动触发报警必须体现：

```text
[AlarmModule] manual trigger alarm
[Mediator] event: MANUAL_ALARM_ON
[Mediator] handle manual alarm as normal alarm flow
[Display] show alarm page
[Buzzer] ON
[LED] RED BLINK
```

启动运行被拒绝必须体现：

```text
[RunModule] request start
[Mediator] event: START_RUN
[Mediator] deny start: alarm active
```

## 14. 禁止事项（非常重要）

AI 生成代码时必须避免：

### 14.1 禁止 colleague 之间直接调用

禁止出现：

```c
display_show_alarm(...);   // 在 AlarmModule 中直接调用
buzzer_on(...);            // 在 AlarmModule 中直接调用
run_module_stop(...);      // 在 DebugModule 中直接调用
```

这些动作只能由中介者触发。

------

### 14.2 禁止让中介者退化成普通全局函数堆

中介者必须是一个结构体对象，内部维护状态和模块引用。

------

### 14.3 禁止在 main 中手工串联所有模块动作

错误示例：

```c
alarm_trigger();
display_show_alarm();
buzzer_on();
led_set_red_blink();
```

正确方式应是：

```c
alarm_module_trigger(&alarm);
```

其余联动由中介者完成。

------

### 14.4 禁止省略手动报警事件

`EVENT_MANUAL_ALARM_ON` 必须存在并演示。

------
