## 1. 任务目标（必须满足）

实现一个基于 C 语言的迭代器模式示例，用于模拟：

> **日志可能存储在不同介质（RAM / Flash）中，日志查看器通过统一迭代器接口顺序访问日志，而不依赖具体存储结构。**

本示例必须体现：

- 存在多个不同类型的日志容器
- 它们内部结构不同
- 提供统一的遍历方式
- 客户端（日志查看器）不关心存储类型
- 不使用 `for` 循环直接访问容器内部数组

------

## 2. 核心场景（必须按此实现）

系统中存在两类日志存储：

### 2.1 RAM 日志（环形缓冲区）

特点：

- 固定容量
- 使用环形结构（head/tail）
- 新日志覆盖旧日志
- 有效数据可能不是从 0 开始

------

### 2.2 Flash 日志（顺序存储）

特点：

- 顺序存储
- 有明确的有效条目数
- 不覆盖旧数据（只追加）

------

### 2.3 日志查看器（客户端）

日志查看器需要：

- 顺序读取日志
- 打印日志内容
- 不关心日志来源（RAM 或 Flash）
- 不关心内部结构（数组 / 环形 / 偏移）

------

## 3. 模式目标（必须体现）

本示例必须体现迭代器模式的核心思想：

- 将“遍历逻辑”从容器中抽离
- 不暴露容器内部结构
- 提供统一访问接口
- 同一客户端可以遍历不同容器

------

## 4. 数据结构定义（必须存在）

------

### 4.1 日志项结构

必须定义统一日志结构：

```c
typedef struct
{
    int id;
    int level;
    char message[64];
} log_entry_t;
```

说明：

- 所有存储类型共享该结构
- 不允许不同容器使用不同日志结构

------

## 5. 抽象迭代器接口（必须存在）

必须定义统一迭代器接口：

```c
typedef struct log_iterator
{
    void (*first)(struct log_iterator *self);
    void (*next)(struct log_iterator *self);
    int  (*is_done)(struct log_iterator *self);
    log_entry_t *(*current)(struct log_iterator *self);
} log_iterator_t;
```

说明：

- `first`：定位到第一个元素
- `next`：移动到下一个
- `is_done`：是否遍历结束
- `current`：获取当前日志项

------

## 6. RAM 日志容器（必须实现）

------

### 6.1 数据结构

```c
#define RAM_LOG_CAPACITY 8

typedef struct
{
    log_entry_t buffer[RAM_LOG_CAPACITY];
    int head;
    int count;
} ram_log_storage_t;
```

说明：

- 使用环形缓冲区
- `head` 表示最新写入位置
- `count` 表示当前有效日志数

------

### 6.2 必须提供接口

```c
void ram_log_init(ram_log_storage_t *self);
void ram_log_add(ram_log_storage_t *self, log_entry_t *entry);
log_iterator_t *ram_log_create_iterator(ram_log_storage_t *self);
```

说明：

- `add` 必须实现环形覆盖逻辑
- `create_iterator` 返回 RAM 专用迭代器

------

## 7. Flash 日志容器（必须实现）

------

### 7.1 数据结构

```c
#define FLASH_LOG_CAPACITY 16

typedef struct
{
    log_entry_t buffer[FLASH_LOG_CAPACITY];
    int count;
} flash_log_storage_t;
```

说明：

- 顺序存储
- `count` 表示有效日志数量

------

### 7.2 必须提供接口

```c
void flash_log_init(flash_log_storage_t *self);
void flash_log_add(flash_log_storage_t *self, log_entry_t *entry);
log_iterator_t *flash_log_create_iterator(flash_log_storage_t *self);
```

说明：

- 不实现覆盖逻辑（简单追加）
- `create_iterator` 返回 Flash 专用迭代器

------

## 8. 具体迭代器实现（必须分别实现）

------

### 8.1 RAM 日志迭代器

必须实现：

```c
typedef struct
{
    log_iterator_t base;
    ram_log_storage_t *storage;
    int index;
    int iterated;
} ram_log_iterator_t;
```

行为要求：

- 从“最旧日志”开始遍历
- 正确处理环形缓冲区
- 遍历 `count` 个有效元素

------

### 8.2 Flash 日志迭代器

必须实现：

```c
typedef struct
{
    log_iterator_t base;
    flash_log_storage_t *storage;
    int index;
} flash_log_iterator_t;
```

行为要求：

- 从 `0` 开始顺序遍历
- 遍历到 `count` 结束

## 9. 客户端（日志查看器，必须存在）

必须实现日志查看函数：

```c
void log_viewer_show(log_iterator_t *it);
```

行为要求：

- 调用 `first`
- 循环调用 `current + next`
- 使用 `is_done` 判断结束
- 打印日志内容

示例逻辑：

```c
it->first(it);

while (!it->is_done(it))
{
    log_entry_t *entry = it->current(it);
    // 打印日志
    it->next(it);
}
```

## 12. 核心设计约束（非常重要）

------

### 12.1 禁止客户端直接访问容器内部

禁止：

```c
for (i = 0; i < storage->count; i++)
```

------

### 12.2 禁止通过 if 判断存储类型遍历

错误示例：

```c
if (type == RAM)
    ...
else
    ...
```

必须通过迭代器统一访问。

------

### 12.3 禁止在客户端写遍历逻辑

遍历必须封装在迭代器中，而不是外部实现。

------

### 12.4 禁止让容器暴露内部结构

例如：

- 不允许直接访问 buffer
- 不允许暴露 head/tail 逻辑

------

## 13. 内存管理要求

本示例可以使用以下方式之一：

- 迭代器对象使用静态分配（推荐）
- 或使用 `malloc/free`

但必须：

- 每个 `create_iterator` 返回独立对象
- 避免内存泄露
